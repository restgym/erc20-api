# Specifications of ERC-20 REST Service

## Original specification

`original/erc20-swagger.json` (Swagger 2.0, JSON), unchanged.

- **Made by**: generated by springfox 2.7.0.
- **Source**: served by the API at `/v2/api-docs`, saved unchanged from the API running in its RESTgym container (2026-10).

## Standardized specification

`standardized/erc20-swagger.json`: the original, formatted (indented with 2 spaces; the original is minified, on one line), with the change below. The other three files are to be provided.

Changes from the original:

- **Version of the API added** (validation error): `info.version: "0.1.0"`, the version of the API packaged (`erc20-rest-service-0.1.0.jar`). Swagger 2.0 requires `info.version`, which the original does not have: the official Swagger Validator (swagger-validator-v2 2.1.9) reported `attribute info.version is missing` on the original. `standardized/validation.json` still has this message: it was written before the change, and the validator will be run again.

## Corrected specification

`corrected/erc20-swagger.json`: the standardized specification (`standardized/erc20-swagger.json`), with the changes below, which make the request bodies match what the API reads. The other three files are to be provided.

Changes from the standardized specification:

- **`ApproveAndCallRequest` completed** (body of `POST /{contractAddress}/approveAndCall`): the properties `spender` (`string`), `value` (`integer`) and `extraData` (`string`) added. In the standardized specification (as in the original), the schema has no properties.
- **`TransferFromRequest` completed** (body of `POST /{contractAddress}/transferFrom`): the property `value` (`integer`) added, besides `from` and `to`.

Why: in the code of the API (`Controller.java` in the original repository), the request classes have Lombok's `@Data`, but `ApproveAndCallRequest` and `TransferFromRequest` declare getters that are not `public` (e.g., `BigInteger getValue()`, `String getSpender()`). springfox documents a property only through a public getter, so it left these properties out of the original; Jackson fills them through the public setters that Lombok generates, so the API reads them, and uses them (`approveAndCallRequest.getSpender()`, `getValue()`, `getExtraData()`; `transferFromRequest.getValue()`). The types are those of the code: `String` (`string`) and `BigInteger` (`integer`, with no format, as springfox writes `BigInteger` elsewhere in the specification).

## Endpoints of the original that may interfere with authentication

RESTgym does not authenticate the requests to this API (it needs no authentication: `auth.py` only rewrites contract addresses). None: the API has no users or credentials.
