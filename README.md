# ERC-20 REST Service for RESTgym

This repository is the RESTgym integration of ERC-20 REST Service. It is meant to be used as a Git submodule of [RESTgym](https://github.com/restgym/restgym) (in `apis/erc20/`), which builds its Docker image and runs it with the testing tools: it does not work on its own.

## How RESTgym runs it

The image starts from the base image of RESTgym for Java 17 (`restgym/api-base:java17`), which contains the proxy and the collection of code coverage. Ganache, a local Ethereum blockchain, runs in the container (deterministic accounts, network id 1337); the API connects to it as `nodeEndpoint`, with the first account as `fromAddress`. When the API is ready, `init-contract.py` deploys a test token contract through the API (`POST /deploy`). The proxy rewrites the requests of the tools (`auth.py`): contract addresses invented by the tools are replaced with the address of the test contract, so that the operations on a contract reach an existing one. The tools reach the API through the proxy of RESTgym, on port 9090.

## Changes made by RESTgym

### API

None.

### Specification

The original specification is `swagger-original.json` (Swagger 2.0): the specification that the API serves at `/v2/api-docs` (springfox 2.7.0), saved unchanged from the API running in its RESTgym container (2026-10-13). `erc20-openapi.json` and `erc20.yaml`, given to the tools, have the same content (OpenAPI 3.0.1, in JSON and YAML). Besides the conversion to OpenAPI 3.0.1, they differ from the original in:

- **Request bodies completed.** `ApproveAndCallRequest` declares `spender`, `value` and `extraData` (it has no properties in the original), and `TransferFromRequest` declares `value` (only `from` and `to` in the original). springfox leaves them out because their getters are not public, but the API reads them: the specifications given to the tools describe the requests that the API accepts.
- **Formats added** to `ContractSpecification`: `int32` for `decimalUnits` and `int64` for `initialAmount`.
- **Schemas renamed**: `TransactionResponse«ApprovalEventResponse»` and `TransactionResponse«TransferEventResponse»` (springfox names, with the characters « ») are `TransactionResponseApprovalEventResponse` and `TransactionResponseTransferEventResponse`.

### Integration

- The local blockchain, the test contract and the rewriting of contract addresses described above.

## Endpoints that may interfere with authentication

RESTgym handles the authentication of the requests, and the tools are not aware of it: an endpoint that ends or changes the session of RESTgym (e.g., logout, login as another user, change or deletion of the user of the proxy, of its password or of its roles) may make the tools fail for the rest of the run. Such endpoints may be removed from the specifications given to the tools.

None: RESTgym does not authenticate the requests to this API (it needs no authentication: `auth.py` only rewrites contract addresses), so no endpoint can end or change a session of RESTgym.
